- **결과**: 보안 수정과 리포트 기능이 함께 반영된 v0.2.0을 빌드·설치했다. 위젯이 다시 정상 실행되었고, 자동 검사(64개 항목) 전체 통과를 확인한 뒤 커밋(`d7e9a4a`)했다.

#### 3. 배포 시 개인정보 노출 여부 확인

#### 4. 위젯 하단 출처 표시의 한글 깨짐 문제 규명 및 수정 (v0.2.1)
- **내가 한 말**: "윈도우 하단에 @mos @Widget는 무슨 문구야?" 이어서 "라벨 규칙을 전체 폴더 명으로 하되 너무 길면 문제가 생길 수 있으니 기준을 정해서 기준을 넘으면 ... 을 넣는것으로 하고, 한글은 왜 한글을 표현할 수 없는지 검토해봐"
- **AI의 반응**: 위젯 하단의 "@프로젝트명" 문구가 어느 작업 중인 프로젝트에서 값을 가져왔는지 알려주는 출처 표시임을 확인했다. 한글 프로젝트 이름이 깨지는 원인도 조사했는데, Claude Code가 대화 기록을 저장할 폴더 이름을 만들 때 한글을 전부 "-"로 바꿔버려서 그 폴더 이름만으로는 원래 이름을 되살릴 수 없다는 것이 원인이었다. 대신 대화 기록 파일 안에 원본 경로가 온전히 남아있는 부분을 찾아 그 값을 쓰도록 바꾸고, 이름이 24자를 넘으면 "…"으로 줄이는 규칙을 정했다.
- **결과**: v0.2.1로 새로 빌드·설치했고, 한글 프로젝트 이름도 정상적으로 표시되는 것을 확인했다. 커밋(`5feeada`) 완료.

#### 5. 스테일 뱃지 위치 문제와 "다시 시도" 버튼 무반응 문제 (v0.2.2~0.2.3)
- **내가 한 말**: "갑자기 위젯하단에 몇분전 기준 뱃지가 생겼네? 그러면서 어느 세션 기준인지에 대한 텍스트가 짤려서 나오고, 몇분 기준인지는 하단으로 옮겨주고 어느 세션 기준인지에 대한 텍스트는 몇자 기준이지 확인해서 알려줘" 이후 "다시 시도를 해도 반응이 없다"
- **AI의 반응**: "N분 전 기준" 뱃지(조회가 실패해 예전 값을 보여주고 있다는 경고 표시)와 출처 표시 글자가 같은 줄에서 자리다툼을 하며 글자가 잘려 보이던 것을 확인하고, 뱃지를 아래 줄로 분리했다(창 높이도 살짝 늘림). 이어서 "다시 시도" 버튼이 반응 없어 보이는 문제를 조사했는데, 실제로는 버튼이 정상 동작하고 있었지만 서버가 요청을 일시 제한(429)한 상태라 눌러도 같은 결과만 나와 화면에 변화가 없었던 것이 원인이었다. 버튼을 누르면 "확인 중…"으로 바뀌었다가 결과가 오면 되돌아오게 하고, 너무 빨리 연달아 누르면 "N초 후에 다시 시도해 주세요" 안내가 뜨도록 고쳤다.
- **결과**: 뱃지 위치 분리와 재시도 버튼 반응 개선을 반영해 v0.2.2, v0.2.3을 차례로 빌드·설치했다(최종적으로 하나의 커밋 `2a9a251`로 정리). 이날 오전 잦은 재설치·재시작으로 서버 요청이 몰려 일시적으로 걸렸던 429 제한은 시간이 지나며 자동으로 풀렸다.

#### 6. MIT 라이선스 설명

#### 7. Windows Defender 보안 경보 원인 진단
- **내가 한 말**: "오늘 아침부터 계속 뜨는데 이거 우리 프로젝트 때문인가?" (Windows Defender의 "Backdoor:PHP/Perhetshell" 경보 화면을 공유)
- **AI의 반응**: 이 프로젝트는 PHP 코드가 전혀 없어 무관하다고 보고 실제 원인을 추적했다. 원인은 보류 중인 다른 프로젝트(아카이브\보류\Echo Mail)에 남아 있던 보안 테스트용 파일(실제 공격 문자열이 담긴 테스트 자료)이었다. 이 파일이 파일 동기화 프로그램(Syncthing)에 의해 계속 이 PC로 복사되려다 Defender에 매번 차단되고, 동기화 프로그램은 이를 실패로 인식해 다시 시도하는 과정이 반복되고 있었다(9시 55분~59분 사이 5번 탐지로 확인).
- **결과**: 위젯과는 무관함을 확인했고, 원본 파일이 있는 장치에서 해당 테스트 파일을 삭제할 것을 권고했다(사용자 조치 대기).

#### 8. 사용량 리포트 측정 기준 확인 및 안내 문구 추가 (v0.2.4)

#### 9. 위젯 가장자리 리사이즈 기능 추가 (v0.3.0)
- **내가 한 말**: "위젯을 윈도우 처럼 테두리를 잡아서 크기를 조정 할 수 없는 거야?" 이어서 "텍스트나 관련 UI들이 모두 커지나?"
- **AI의 반응**: 지금은 설정에서 크기 조정을 일부러 막아둔 상태였을 뿐, 테두리를 잡아 늘리는 기능 자체는 만들 수 있다고 확인했다. 글자 크기는 그대로 두고 여백만 넓히는 방식 대신, 창을 넓히면 글자·게이지·차트가 화면을 확대하듯 함께 커지는 방식을 선택했다고 설명했다 — 어제(7/29) 글자가 작다는 지적이 있었던 만큼 리사이즈를 원하는 진짜 이유는 "가독성"이라고 판단했기 때문이다. 확장 모드에서만 가장자리를 드래그해 크기를 바꿀 수 있게 하고(최소 240×300, 최대 560×900), 너비를 기준으로 0.8~2.5배까지 화면 전체가 확대되도록 만들었다. 높이를 비율보다 더 늘리면 남는 공간은 24시간 사용량 차트가 채우고, 조정한 크기는 설정에 저장돼 재시작 후에도 유지되며, 접었다 펴는 컴팩트 모드는 지금처럼 고정 크기를 유지하도록 했다.
- **결과**: v0.3.0을 빌드·설치해 실행 확인(자동 검사 65개 항목 전체 통과, 화면 코드 오류 0건). 가장자리를 잡아 늘리면 실제로 글자와 그래프가 함께 커지는 것을 확인했다. 위젯이 화면 우측 하단에 붙어있을 때는 오른쪽·아래쪽 가장자리가 화면 밖이라 잡기 어려울 수 있어, 왼쪽·위쪽 가장자리를 이용하도록 안내했다.

### 발생한 문제와 해결
- **문제**: 어제 제거 테스트 이후 재설치를 하지 않아 위젯이 실행되지 않고 있었다.
- **해결**: 최신 버전을 다시 빌드해 설치하고 실행을 확인했다.
- **문제**: 위젯 하단 출처 표시에서 한글 프로젝트 이름이 깨져서 나왔다.
- **해결**: Claude Code가 폴더 이름을 만들 때 한글을 "-"로 바꿔버리는 것이 원인임을 확인하고, 대화 기록 안에 남아있는 원본 경로 값을 사용하도록 바꿨다.
- **문제**: 위젯 하단에 "N분 전 기준" 뱃지가 새로 생기면서 출처 표시 글자가 잘려 보였다.
- **해결**: 뱃지를 별도 줄로 분리해 서로 자리를 침범하지 않게 했다.
- **문제**: "다시 시도" 버튼을 눌러도 반응이 없어 보였다.
- **해결**: 실제로는 서버 요청 제한(429)으로 결과가 매번 똑같이 나와 화면 변화가 없었던 것으로 확인, 버튼에 "확인 중…" 표시와 연타 방지 안내를 추가해 눌렀다는 것이 눈에 보이도록 했다.
- **문제**: Windows Defender가 아침 내내 보안 경보를 반복해서 띄웠다.
- **해결**: 위젯과 무관한, 다른 보류 프로젝트의 테스트 파일이 동기화 프로그램에 의해 계속 재시도되며 매번 차단당하고 있던 것으로 원인을 밝혔다.
- **문제**: 위젯 크기를 드래그로 조정한 뒤 원래 크기로 되돌리려 해도, 드래그만으로는 정확히 맞출 방법이 없었다.
- **해결**: 설정 창에 "기본 크기로" 버튼을 추가해 한 번에 원래 크기(260×390)와 배율(1.0배)로 복귀하도록 했다.
- **문제**: 새(다른) PC에서 프로젝트를 처음 빌드했더니 데이터 저장 기능 부분에서 컴파일이 실패했다.
- **해결**: 원인이 그 PC의 Rust 개발 도구 버전(1.93.1)이 오래된 것임을 확인하고, 최신 버전(1.97.1)으로 업데이트한 뒤 다시 빌드해 성공시켰다. 프로젝트에는 최소 1.94 이상의 버전이 필요하다는 것이 이번에 새로 확인됐다(기존 문서에는 "1.95"로만 적혀 있어 이게 권장인지 최소 요구사항인지 불명확했음).
