#### 메모리 목표 미달성 (2026-07-28)

release 빌드 실측, 프로세스 트리 전체:

| 프로세스 | WorkingSet | PrivateBytes |
|---|---|---|
| claude-usage-widget | 37.2MB | **7.6MB** |
| msedgewebview2 × 6 | 346.9MB | 169.7MB |
| **합계** | **384.1MB** | **177.3MB** |

**앱 자체는 7.6MB** 이고 나머지는 전부 WebView2 런타임이다. PRD의 150MB 목표는 WebView2 의 프로세스 구조(브라우저·GPU·네트워크·렌더러 분리)를 모르고 잡은 값으로 보인다. 선택지:

1. 목표를 WebView2 현실에 맞게 상향 (예: 200MB) — 앱 코드로 줄일 여지가 거의 없다
2. UI 를 네이티브(egui 등)로 교체 — /bootstrap 에서 비교 후 탈락시킨 안. 차트·테마·반투명 구현 비용이 다시 발생한다

→ **사용자 판단 필요.** 그때까지 KPI 미달성으로 남겨 둔다.

## 의존관계 다이어그램

```
M1 (PoC: credentials → endpoint 검증) ⚠️ Go/No-Go
 └→ M2 (스캐폴딩 → credentials/usage-client/poller)
     ├→ M3 (위젯 UI, 트레이)  ─┐
     ├→ M4 (알림, 설정)        ├→ M6 (패키징·안정화)
     └→ M5 (히스토리, 차트)   ─┘
M3~M5는 M2 완료 후 병렬 진행 가능 (단, 5.2 차트는 3.1 확장 모드 필요)
```
