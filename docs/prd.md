# Claude Usage Widget - PRD (Product Requirements Document)

> 작성일: 2026-07-20
> 버전: 1.0
> 기반 문서: planning.md

## 1. Problem Statement

Claude Code(Pro/Max 구독)는 5시간 세션 한도와 주간 한도가 있지만, 현재 사용률을 확인하려면 Claude Code 내부에서 `/usage`를 실행하는 방법뿐이다. 작업에 몰입한 상태에서는 한도 임박을 인지하지 못해 세션이 갑자기 차단되는 일이 잦다.

**해결책**: PC에 이미 로그인된 Claude Code의 OAuth 자격증명을 재사용하여, 별도 로그인 없이 사용량을 상시 표시하는 Windows 11 트레이 + 플로팅 위젯 앱.

## 2. 사용자 스토리

### 핵심 시나리오
- 사용자로서, 데스크톱 구석의 위젯에서 세션/주간 한도 사용률을 흘끗 확인할 수 있다. 그래서 Claude Code를 중단하지 않고 작업 페이스를 조절할 수 있다.
- 사용자로서, 한도 80% 도달 시 토스트 알림을 받을 수 있다. 그래서 차단 전에 중요한 작업을 먼저 끝낼 수 있다.
- 사용자로서, 리셋까지 남은 시간을 볼 수 있다. 그래서 휴식·재개 타이밍을 계획할 수 있다.

### 상세 시나리오
| # | 사용자 | 행동 | 기대 결과 |
|---|--------|------|----------|
| 1 | 구독 사용자 | PC 부팅 | 트레이에 자동 시작, 마지막 위치에 위젯 표시, 60초 내 최신 사용률 반영 |
| 2 | 구독 사용자 | 위젯을 흘끗 봄 | 세션 %, 주간 %, 리셋 카운트다운이 게이지로 보임 |
| 3 | 구독 사용자 | 위젯 더블클릭(또는 확장 버튼) | 확장 모드: 상세 수치 + 히스토리 차트 표시 |
| 4 | 구독 사용자 | 세션 사용률 80% 도달 | Windows 토스트 알림 1회 수신 (중복 알림 없음) |
| 5 | 구독 사용자 | 세션 리셋 시각 도래 | 게이지 0%로 갱신 + (설정 시) 리셋 알림 |
| 6 | 구독 사용자 | 트레이 아이콘 우클릭 | 메뉴: 위젯 표시/숨김, 지금 새로고침, 설정, 종료 |
| 7 | 구독 사용자 | 트레이 아이콘에 마우스 오버 | 툴팁: "세션 42% · 주간 61% · 리셋 1:23 후" |
| 8 | 토큰 만료 사용자 | 위젯 확인 | "Claude Code를 한 번 실행해 인증을 갱신해 주세요" 안내 표시 (크래시 없음) |
| 9 | 네트워크 끊김 사용자 | 위젯 확인 | 마지막 조회값 + "N분 전 기준" 스테일 표시 |
| 10 | 구독 사용자 | 설정 열기 | 폴링 주기, 알림 임계값, 테마, 투명도, 자동 시작 변경 가능 |

## 3. Functional Requirements

### 3.1 필수 기능 (Must Have)

**FR-1. 자격증명 로드**
- [ ] `%USERPROFILE%\.claude\.credentials.json`에서 OAuth accessToken을 읽기 전용으로 로드
- [ ] 파일 없음/포맷 다름/토큰 만료(expiresAt 경과) 각각을 구분해 사용자 안내 상태로 매핑
- [ ] 자격증명 접근 로직을 어댑터 모듈로 분리 (경로·포맷 변경 대비)
- [ ] 토큰을 로그·설정·히스토리 등 어디에도 저장·출력하지 않음

**FR-2. 사용량 조회 클라이언트**
- [ ] Claude Code가 사용하는 OAuth usage 엔드포인트 호출 (M1 PoC에서 URL·헤더·응답 스키마 확정)
- [ ] 응답에서 세션(5시간) 사용률 %, 주간 사용률 %, Opus 주간 %(존재 시), 각 리셋 시각(UTC) 파싱
- [ ] 방어적 파싱: 알 수 없는 필드 무시, 필수 필드 누락 시 "조회 불가" 상태로 처리 (크래시 금지)
- [ ] HTTP 401 → "재인증 필요", 5xx/타임아웃 → 지수 백오프 재시도 (최대 3회)

**FR-3. 폴링 서비스**
- [ ] 설정된 주기(기본 60초, 하한 30초)로 자동 조회
- [ ] 조회 결과를 UI(위젯·트레이)와 히스토리 저장소에 브로드캐스트
- [ ] 수동 새로고침 트리거 지원 (연타 방지 스로틀 5초)
- [ ] 절전 모드 복귀 시 즉시 1회 조회

**FR-4. 플로팅 위젯 창**
- [ ] 프레임리스, always-on-top, 작업 표시줄 미표시(스킵 태스크바) 소형 창
- [ ] 컴팩트 모드: 세션/주간 게이지 2개 + 리셋 카운트다운
- [ ] 확장 모드: 상세 수치(%, 리셋 절대시각) + 히스토리 차트
- [ ] 드래그로 이동, 위치·모드·크기 저장 후 재시작 시 복원
- [ ] 사용률 구간별 색상: 정상(<60%) / 주의(60~85%) / 위험(>85%)
- [ ] 카운트다운은 로컬 시간 기준 1분 단위 갱신

**FR-5. 트레이 상주**
- [ ] 트레이 아이콘 상시 표시, 사용률 최고값 기준 색상 변화 (정상/주의/위험)
- [ ] 마우스 오버 툴팁: 세션 %, 주간 %, 다음 리셋 요약
- [ ] 우클릭 메뉴: 위젯 표시/숨김, 지금 새로고침, 설정 열기, 시작 시 자동 실행 토글, 종료
- [ ] 위젯 창을 닫아도 앱은 트레이에 상주 (완전 종료는 트레이 메뉴에서만)

### 3.2 권장 기능 (Should Have)

**FR-6. 임계값 알림**
- [ ] 세션/주간 사용률이 설정 임계값(기본 80%, 95%) 도달 시 Windows 토스트 알림
- [ ] 동일 임계값·동일 리셋 주기 내 중복 알림 방지
- [ ] 리셋 완료 시 알림 (기본 꺼짐, 설정으로 활성화)

**FR-7. 히스토리 & 차트**
- [ ] 폴링 스냅샷(타임스탬프, 세션 %, 주간 %)을 로컬 저장 (SQLite 또는 JSONL)
- [ ] 보존 기간 90일, 초과분 자동 정리
- [ ] 확장 모드에서 최근 24시간 세션 사용률 추이 차트
- [ ] 일별/주별 집계 뷰 (요일별 사용 패턴)

**FR-8. 설정**
- [ ] 설정 UI: 폴링 주기(30초~10분), 알림 임계값, 알림 on/off, 테마(라이트/다크/시스템), 위젯 투명도, 자동 시작
- [ ] 설정은 로컬 JSON으로 저장, 즉시 적용 (앱 재시작 불필요)
- [ ] Windows 시작 시 자동 실행 등록/해제

### 3.3 선택 기능 (Nice to Have)

- [ ] 인스톨러 패키징 (NSIS/MSI), 버전 표시
- [ ] 자동 업데이트 (GitHub Releases 기반)
- [ ] 로컬 트랜스크립트(JSONL) 파싱으로 토큰·비용 통계 보강 (하이브리드, 차기 확장)
- [ ] 위젯 클릭스루(click-through) 모드

## 4. Non-Goals

- Windows 11 위젯 보드(Win+W) 통합 — MSIX + COM 프로바이더 비용 큼, 차기 버전 검토
- macOS / Linux 지원
- 다중 계정 지원 (Claude Code 자격증명은 PC당 1계정)
- API 종량제(Console/Admin API) 사용량 표시
- 자체 OAuth 로그인 플로우 구현 (Claude Code 인증 재사용으로 대체)
- 사용량 데이터의 외부 전송·클라우드 동기화

## 5. Design Considerations

### 5.1 UI/UX 방향
- **컴팩트 위젯 (기본)**: 약 220×90px. 가로 게이지바 2개(세션/주간) + 우측에 리셋 카운트다운. 반투명 다크 배경, 모서리 라운드
- **확장 위젯**: 약 320×360px. 수치 카드(세션/주간/Opus) + 24시간 추이 차트 + 마지막 갱신 시각
- **상태 표현**: 데이터 정상(색상 게이지) / 스테일("N분 전 기준" 뱃지) / 재인증 필요(안내 카드) / 조회 불가(회색 + 재시도 버튼)
- 다크/라이트 테마, Windows 11 스타일(Mica 유사 반투명, Segoe UI Variable)

### 5.2 데이터 모델
```
Credentials (읽기 전용, 외부 파일)
  - accessToken, expiresAt, subscriptionType

UsageSnapshot (폴링 결과)
  - fetchedAt: datetime
  - session: { utilization: %, resetsAt: datetime }
  - weekly: { utilization: %, resetsAt: datetime }
  - weeklyOpus?: { utilization: %, resetsAt: datetime }

Settings (로컬 JSON)
  - pollingIntervalSec, thresholds[], notificationsEnabled,
    theme, opacity, autoStart, widgetPosition, widgetMode

HistoryEntry (로컬 저장소)
  - timestamp, sessionPct, weeklyPct, opusPct?
```

### 5.3 API 설계 방향 (내부 모듈 경계)
```
credentials 모듈: load() → Token | NotFound | Expired | ParseError
usage-client 모듈: fetchUsage(token) → UsageSnapshot | AuthError | NetworkError | SchemaError
poller 모듈:     start/stop/refreshNow, 이벤트 발행(snapshot, error)
history 모듈:    append(snapshot), query(range), prune()
notifier 모듈:   evaluate(snapshot) → 토스트 발송 (중복 억제 상태 관리)
UI(위젯/트레이): 이벤트 구독 → 렌더링
```

## 6. 기술적 제약사항

- **성능**: 유휴 CPU ~0%, 메모리 150MB 이하, 앱 시작 → 첫 표시 3초 이내
- **보안**: 자격증명 읽기 전용, 토큰 비출력·비전송(usage 조회 요청 제외), 히스토리에 토큰 미포함
- **안정성**: 네트워크 오류·API 스키마 변경 시에도 크래시 없이 상태 UI로 강등, 24시간+ 연속 상주
- **호환성**: Windows 11 (WebView2 Evergreen 기본 탑재), Windows 10 22H2는 베스트 에포트
- **비공식 API 리스크**: usage 엔드포인트는 비공식 — M1 PoC를 Go/No-Go 게이트로 설정. 실패 시 폴백: 로컬 트랜스크립트 파싱 방식으로 전환 (별도 재기획)

## 7. 성공 기준 (KPI)

| 지표 | 목표 | 측정 방법 |
|------|------|---------|
| 데이터 정확도 | Claude Code `/usage` 표시값과 일치 (±1 폴링 주기) | 수동 대조 10회 |
| 상주 안정성 | 24시간 크래시 0회, 메모리 ≤150MB | 장시간 실행 테스트 |
| 알림 적시성 | 임계값 도달 후 1분(=1 폴링 주기) 내 알림 | 임계값 낮춰 실측 |
| 시작 경험 | 부팅 → 위젯 표시까지 개입 0회 | 재부팅 테스트 |
| 히스토리 | 7일+ 누적, 차트 조회 가능 | 실사용 확인 |
