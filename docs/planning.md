# Claude Usage Widget - 기획서

> 작성일: 2026-07-20
> 프로젝트 유형: 자동화/도구 (Windows 데스크톱 유틸리티)
> 규모: 풀 버전

## 1. 프로젝트 개요

### 1.1 배경 및 목적
Claude Code(Pro/Max 구독)는 5시간 세션 한도와 주간 한도가 있어, 한도에 임박하면 작업이 강제로 중단된다. 현재 한도를 확인하려면 Claude Code 안에서 `/usage`를 직접 실행해야 하며, 작업 중 수시로 확인하기 번거롭다.

이 프로젝트는 **PC에 이미 로그인된 Claude Code의 인증 정보를 재사용**하여, 별도 로그인 없이 사용량(세션/주간 한도 %)을 데스크톱에서 상시 확인할 수 있는 Windows 11 위젯을 만든다.

### 1.2 목표
- 핵심 목표: Claude Code를 열지 않고도 세션/주간 한도 사용률과 리셋 시각을 한눈에 확인
- 부가 목표:
  - 한도 임박 시 알림으로 작업 중단을 미리 대비
  - 사용 패턴 히스토리를 기록·시각화하여 구독 활용도 파악
  - 트레이 상주형으로 시스템 부하 최소화

### 1.3 타겟 사용자
- 주요 사용자: 본인 (Claude Code Pro/Max 구독자, Windows 11)
- 확장 가능성: 동일한 니즈를 가진 Claude Code 사용자 (GitHub 공개 배포 시)
- 사용 시나리오:
  - 코딩 작업 중 화면 구석의 위젯으로 남은 한도를 흘끗 확인
  - 한도 80% 도달 시 토스트 알림을 받고 작업 우선순위 조정
  - 리셋 카운트다운을 보고 휴식/재개 타이밍 결정
  - 주간 사용 패턴 차트로 요일별 사용량 파악

## 2. 핵심 기능

| # | 기능명 | 설명 | 우선순위 |
|---|--------|------|---------|
| 1 | 인증 재사용 | Claude Code가 저장한 OAuth 자격증명(`~/.claude/.credentials.json`)을 읽기 전용으로 재사용. 별도 로그인 없음 | 필수 |
| 2 | 사용량 조회 | 비공식 OAuth usage 엔드포인트로 5시간 세션 %, 주간 %, (Max의 경우 Opus 주간 %) 및 리셋 시각 조회 | 필수 |
| 3 | 플로팅 위젯 | 항상 위(always-on-top) 소형 창. 게이지/바 형태 표시, 드래그 배치, 위치 기억, 컴팩트↔확장 전환 | 필수 |
| 4 | 트레이 상주 | 시스템 트레이 아이콘(사용률에 따른 색상 변화), 툴팁 요약, 우클릭 메뉴(위젯 표시/설정/종료) | 필수 |
| 5 | 자동 갱신 | 설정 가능한 폴링 주기(기본 60초)로 자동 갱신, 수동 새로고침 버튼 | 필수 |
| 6 | 리셋 카운트다운 | 세션/주간 리셋까지 남은 시간 실시간 표시 | 필수 |
| 7 | 임계값 알림 | 사용률 80%/95%(설정 가능) 도달 시 Windows 토스트 알림, 리셋 완료 알림 | 권장 |
| 8 | 히스토리 & 차트 | 폴링 스냅샷을 로컬 저장, 시간대별/일별 사용 패턴 차트 | 권장 |
| 9 | 설정 | 폴링 주기, 알림 임계값, 테마(라이트/다크/시스템), 투명도, Windows 시작 시 자동 실행 | 권장 |
| 10 | 패키징 배포 | 인스톨러(설치/제거), 버전 관리. 자동 업데이트는 선택 | 선택 |

## 3. 기술 방향

> 최종 기술스택은 `/bootstrap` 단계에서 확정. 아래는 기획 시점의 방향성.

- **앱 프레임워크**: Tauri 2 (Rust + WebView2) 제안
  - 이유: 트레이·always-on-top·프레임리스 창·자동 시작을 기본 지원, 번들 수 MB로 상주 앱에 적합(Electron 대비 메모리 1/5 수준), UI는 웹 기술로 차트 구현 용이
  - 대안: WPF/.NET 8 (완전 네이티브, C# 경험 활용 가능하나 차트/테마 구현 비용 큼)
- **프론트엔드(위젯 UI)**: 경량 웹 스택 (Vanilla TS 또는 Svelte) + 경량 차트 라이브러리
- **백엔드**: 없음 (완전 로컬 앱). Rust 사이드에서 자격증명 읽기 + HTTPS 호출 + 폴링
- **데이터 저장**: 로컬 파일 (설정 JSON + 히스토리 SQLite 또는 JSONL)
- **인프라/배포**: GitHub 저장소, Tauri 번들러로 NSIS/MSI 인스톨러 생성

## 4. 제약사항 및 고려사항

- **비공식 API 의존**: 구독 사용량 조회는 공식 공개 API가 없어 Claude Code가 내부적으로 쓰는 OAuth usage 엔드포인트를 사용한다. Anthropic이 예고 없이 변경할 수 있으므로:
  - M1에서 PoC로 엔드포인트 동작을 먼저 검증 후 본 개발 진행 (Go/No-Go 게이트)
  - 응답 스키마 변경에 대비한 방어적 파싱 + "조회 불가" 상태 UI 필수
- **자격증명 보안**: `.credentials.json`은 읽기 전용으로만 접근. 토큰을 로그·히스토리·외부로 절대 내보내지 않음. 갱신(refresh)은 1차적으로 Claude Code에 위임하고, 토큰 만료 시 위젯은 "Claude Code를 한 번 실행해 주세요" 안내
- **토큰 저장 위치 변경 리스크**: Claude Code 버전업으로 자격증명 저장 방식이 바뀔 수 있음 → 경로/포맷을 어댑터로 분리
- **상주 앱 부하**: CPU 유휴 시 ~0%, 메모리 150MB 이하 목표. 폴링 주기 하한(30초)으로 API 부담 방지
- **범위 제한**: Claude Code 자격증명은 PC당 1계정이므로 다중 계정은 범위 제외. API 종량제(Console) 사용량도 제외
- **시간 제약**: 개인 프로젝트, 마일스톤 단위로 진행 (상세는 tasks.md)

## 5. 성공 기준

- 위젯 표시값이 Claude Code `/usage`와 ±1분 이내 데이터로 일치
- 24시간 이상 상주 시 크래시·메모리 누수 없음 (메모리 150MB 이하 유지)
- 한도 80%/95% 도달 시 1분 이내 토스트 알림 수신
- PC 부팅 → 자동 시작 → 위젯 표시까지 사용자 개입 0회
- 7일 이상 히스토리가 누적되고 차트로 조회 가능
